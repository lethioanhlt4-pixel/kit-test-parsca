## Yêu cầu cho mỗi Test Case:

### 1. Đánh giá rủi ro (Risk Assessment)

Dùng risk đã chốt ở Bước 4 (mặc định):
- **High 🔴:** ROLE, LOGIN, SESS, SCOPE, PSTAT, PFORM, CSV, WEB, API → 8–15+ TC/module, đủ Happy + Negative + Boundary + Edge + Security
- **Medium 🟡:** PLIST, IMG, ORDD, PAY, PROF → 4–8 TC/module
- **Low 🟢:** PDTL, DASH, ORD, REV, SET → 2–4 TC/module, happy path + kiểm hiển thị

Áp dụng checklist validation theo loại field:

| Loại Field | Validation cần test |
|---|---|
| **Text (Name, Brand, Address...)** | Required · Min/Max length · Whitespace-only · Leading/trailing spaces (trim) · Ký tự đặc biệt (`<>&"'`) · XSS (`<script>alert(1)</script>`) · SQL injection (`' OR 1=1--`) · Unicode/Emoji |
| **SKU / Code** | Required · Dấu cách · Chữ thường → HOA · Trùng (của mình / V2 / Admin) · Ký tự đặc biệt · Max length |
| **Email** | Format · Thiếu `@` · Thiếu domain · `a@b.c` (kiểm lỏng ở Payouts) · Max length |
| **Phone** | Chỉ số · Chữ cái (Payouts nhận cả chữ — ghi nhận) · Dấu `-`, `.`, khoảng trắng |
| **Date** | Ngày tương lai (Date of birth) · Ngày không tồn tại · Năm nhuận |
| **Number / Currency (Price, Compare at, Stock, Rating, Year)** | Min/Max · Số âm · 0 · Thập phân (≤ 4 chữ số / không cho phép) · Ký tự không phải số · `1.2.3` · Leading zeros · Overflow |
| **Dropdown (Department, Subcategory, Brand, Status, Condition, Availability)** | Mặc định · Tất cả option · Phụ thuộc (đổi department) · Required chưa chọn |
| **Checkbox (New, In stock, Terms, Same as contact address)** | Mặc định · Check/Uncheck · Bị bỏ qua (In stock tính lại) · Required |
| **File Upload (ảnh, avatar, CSV)** | Loại hợp lệ/không (svg, heic, pdf, text đổi đuôi) · Biên 10 MB (10.000.000 B / 10.485.760 B / 11.534.336 B) · File rỗng · Nhiều file vượt chỗ trống · Chọn lại cùng file · Huỷ hộp chọn |
| **Tag Input (Alternate part numbers)** | Trùng · Trim · Xoá từng cái · Enter không submit form |
| **Textarea (Mô tả)** | Max length · Xuống dòng · HTML tags |

### 5b. Scenarios Chuyên Sâu & Non-Functional Checklist

1. **Double Submit & Concurrent Edit:** bấm "Add Product" 2 lần; 5 request cùng SKU (race → chỉ 1 thành công); 2 tab cùng sửa 1 sản phẩm.
2. **Session & Network Resilience:** token hết hạn khi đang ở form / đang upload (upload 401 không tự gửi lại); refresh token dùng lại → "Invalid session"; mất mạng khi import → khung "Connection lost before the server answered…".
3. **Localization & UTF-8 / Emoji:** tên sản phẩm tiếng Việt có dấu, emoji (`😀🚀`), ký tự đa ngôn ngữ; slug sinh ra hợp lệ.
4. **Keyboard Accessibility (A11y):** Tab order form sản phẩm, Enter trong Alternate part numbers không submit, Esc đóng hộp thoại "Delete product?".
5. **HTTP Status Codes (API TCs):** `200`, `201`, `204` (DELETE), `400` (trường lạ), `401`, `403` (API quản trị), `404` (sản phẩm người khác), `409` (SKU/slug trùng), `429` (login), `5xx`.

**Ví dụ Field-Level Validation — trường "Stock count" (PFORM):**
```
Đặc tính: bắt buộc, số nguyên, ≥ 1, mặc định 0

- TC: Để mặc định 0 → "Stock count must be at least 1", không lưu
- TC: Xoá trống → "Stock count required"
- TC: Nhập 1 → Hợp lệ (biên dưới)
- TC: Nhập 1.5 → "Stock count must be a whole number"
- TC: Nhập -1 → Báo lỗi
- TC: Nhập 999 + bỏ tick "In stock" → Lưu thành công, sản phẩm vẫn "In stock" (BE tính lại)
```

> Xác định đặc tính từng field (type, required, min/max, format, unique, thông báo lỗi) từ doc trước khi sinh TC. Field nào doc không ghi giới hạn → ghi `@SuyLuan` và đưa vào Q-NEW.

### 6. Kỹ thuật thiết kế Test Case (Test Design Techniques)

**a) Equivalence Partitioning**
```
Chủ sở hữu sản phẩm khi V1 thao tác:
- Lớp "của mình" (V1)   → cho phép
- Lớp "vendor khác" (V2) → 404 "Product not found"
- Lớp "admin tạo"        → 404 "Product not found"
```

**b) Boundary Value Analysis**
```
Số ảnh Gallery (1–5):
- 0 ảnh → "At least one image is required"
- 1 ảnh → Hợp lệ
- 5 ảnh → Hợp lệ, bộ đếm "5/5 images"
- chọn thêm khi đã 5 → "A product can have at most 5 images"

CSV số dòng (≤ 50.000): 50.000 → nhận; 50.001 → "The file has 50001 rows; the limit is 50000 per import. Please split it."
```

**c) Decision Table**
```
GET /products/admin/:id (sản phẩm của V2):
| Vai          | Kết quả |
|--------------|---------|
| anonymous    | 401     |
| user         | 403     |
| vendor V1    | 404     |
| vendor V2    | 200     |
| admin        | 200     |
```

**d) State Transition**
```
Sản phẩm: Active ↔ Draft ↔ Archived ; mọi trạng thái → Xoá (204)
Website: Active → hiện ngay; Draft / Archived / Xoá → 404 trên storefront
Test: mọi transition + kiểm website sau mỗi transition; Import CSV luôn → Active (cột status bị bỏ qua)
```

> Chọn kỹ thuật phù hợp cho từng Module/Field dựa trên đặc tính dữ liệu và logic nghiệp vụ.
