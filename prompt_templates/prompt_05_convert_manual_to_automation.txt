# CONSTRAINTS
1. Page Object Model (POM):
   - Mọi locator phải nằm trong Page Class (kế thừa BasePage), không viết inline page.locator() trong spec file.
   - Các màn giả lập ([GIẢ LẬP] như Dashboard, Orders, Reviews, Payouts, Settings) đặt trong pages/vendor/simulated/.
2. Locator Strategy:
   - Tuân thủ thứ tự: getByRole > getByLabel > getByPlaceholder > getByTestId > getByText > id/name > CSS > XPath.
   - Inspect DOM thực tế trước khi chốt locator, tuyệt đối không đoán selector từ tên nhãn trong tài liệu BA.
3. Xử lý đồng bộ & Waits:
   - CẤM dùng page.waitForTimeout() hoặc sleep cứng.
   - Dùng expect(locator).toBeVisible(), toHaveURL(), và page.waitForResponse() đăng ký trước thao tác click.
4. Quản lý dữ liệu test:
   - Sử dụng utils/dataFactory.ts để tạo dữ liệu ngẫu nhiên có tiền tố AUTO- (vd: AUTO-<MOD>-<timestamp>).
   - Tuyệt đối không hardcode mật khẩu, email cá nhân thật, hoặc ID sản phẩm cố định (dùng biến môi trường ${VENDOR1_EMAIL}, ${V2_PRODUCT_ID}...).
   - Đăng ký dữ liệu tạo mới vào cleanup registry để tự động xoá trong afterEach.
5. Quy tắc chuyển đổi nhãn:
   - TC có tag @CodeHienTai: Đánh dấu test.fixme() kèm annotation mã câu hỏi PO (Q-Vx), không ép pass khi hành vi BE/FE đang có mâu thuẫn nghiệp vụ.
   - TC có tag @GiaLap: Chỉ assert giao diện và assert KHÔNG có request API cấm, không assert lưu DB.
   - TC có tag @NeedDevSupport: Sử dụng test.skip() có điều kiện nếu môi trường test thiếu hỗ trợ.
6. Chuẩn hoá tiêu đề Test Spec:
   - Tiêu đề test phải bắt đầu bằng TC ID tương ứng:
     test('PARSCA_SCOPE_TC_003 — V1 mở trang chi tiết sản phẩm V2 @Smoke @DataScope', async ({ ... }) => { ... })

# OUTPUT FORMAT
1. Tóm tắt phân tích & tiếp cận (2-3 câu).
2. Danh sách file thay đổi hoặc tạo mới (Pages, Fixtures, Specs, Utils).

4. Kết quả thực thi test: Báo cáo kết quả chạy test ít nhất 2 lần liên tiếp trong UI/Headed mode.
