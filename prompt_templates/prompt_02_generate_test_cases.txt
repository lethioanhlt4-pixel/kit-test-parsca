# CONSTRAINTS
1. Phân tích requirement, xác định các luồng:
   - Happy Path (vd: tạo sản phẩm tối thiểu → toast "Saved" → về /vendor/products)
   - Alternate Path (vd: đổi department → subcategory bị xoá, brand về mặc định)
   - Exception Path (vd: 409 SKU trùng, hết phiên khi bấm lưu, ảnh > 10 MB)
2. Phát hiện Ambiguities (AMB-xx) và đặt câu hỏi PO theo format Q-Vx; liên kết Q đang mở (Q-V2, Q-V4, Q-V5, Q-V6, Q-V8, Q-V9).
3. Đánh giá Risk Level theo catalog PARSCA:
   - 🔴 High (ROLE, LOGIN, SESS, SCOPE, PSTAT, PFORM, CSV, WEB, API): 8-15+ TCs, Priority Critical
   - 🟡 Medium (PLIST, IMG, ORDD, PAY, PROF): 4-8 TCs, Priority High
   - 🟢 Low (PDTL, DASH, ORD, REV, SET): 2-4 TCs, Priority Medium / Low
4. Áp dụng kỹ thuật thiết kế test case:
   - Equivalence Partitioning (chủ sở hữu V1 / V2 / Admin; status active / draft / archived / lạ; department marine / auto / door / tools / lạ)
   - Boundary Value Analysis (stockCount 0/1; ảnh 0/1/5/6; ảnh 10.000.000 B / 10.485.760 B / 11.534.336 B; price 4/5 chữ số thập phân; rating 5 / 5.1)
   - Decision Table (ma trận 4 vai × endpoint; guard 4 vai × /vendor, /admin, /profile, /orders)
   - State Transition (Active ↔ Draft ↔ Archived → Xoá; hiển thị trên storefront)
   - Error Guessing (SKU chữ thường / có dấu cách; `<script>` trong tiêu đề; trường lạ createdBy → 400; double submit)
5. Bắt buộc phủ mọi điểm GHI CHÚ CHO TESTER của doc (≥ 1 TC mỗi điểm). Điểm THEO CODE HIỆN TẠI → TC ghi "⚠️ THEO CODE HIỆN TẠI → ghi Q-Vx, không PASS" + tag @CodeHienTai. Màn [GIẢ LẬP] → tag @GiaLap, KHÔNG viết Expected "dữ liệu được lưu".
6. Luôn kiểm business rules liên quan: BR-02 (sản phẩm người khác → 404 "Product not found", KHÔNG phải 403), BR-05 (trường lạ → 400), BR-06 (SKU/slug unique toàn hệ thống, BE đổi SKU thành CHỮ HOA), BR-07 (Active hiện ngay trên website), BR-09 (ảnh jpeg/png/webp/gif ≤ 10 MB, 1–5 ảnh).
7. Bao phủ: Happy path, Negative, Boundary, Edge, Security/Permission/Data scope, Double submit, Session (access_token 15 phút, refresh), Rate limit (5 lần/phút/IP → 429), Keyboard A11y, UTF-8/Emoji.
8. Test Data phải CỤ THỂ theo .agent/rules/test-data.md:
   - Đúng: "Nhập SKU: AUTO-PFORM12-20261020", "Name: Auto Pform TC12 20261020", "Price: 0.00001"
   - Sai: "Nhập SKU hợp lệ"
   - Credentials chỉ ghi tên biến: ${VENDOR1_EMAIL}, ${ROLE_TEST_NEW_PASSWORD}
9. Expected Result cụ thể: status code + thông báo nguyên văn + số lượng (vd: 409 `Product with SKU "AUTO-PFORM12-20261020" already exists`). Không viết "hiển thị đúng".
10. AI Self-Quality Gate: TC ID unique 100%, Step N ↔ Expected N, test data cụ thể, mỗi field có Positive / Negative / Boundary / Edge, đủ 3 cột automation.
