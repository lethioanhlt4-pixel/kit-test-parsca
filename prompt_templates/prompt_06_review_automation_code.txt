# CONSTRAINTS
Đánh giá toàn diện dựa trên 5 khía cạnh cốt lõi:

1. Nhóm A - Selector & DOM Strategy (.agent/rules/selectors.md):
   - Đã tuân thủ thứ tự ưu tiên: getByRole > getByLabel > getByPlaceholder > getByTestId > getByText > id/name > CSS > XPath?
   - Có vi phạm class hash động, utility CSS dễ gãy, hoặc XPath tuyệt đối không?
   - Toàn bộ locator đã được đóng gói trong Page Object chưa, hay vẫn còn inline trong spec?
   - Đã xử lý scoping đúng chưa (ví dụ: filter theo dòng bảng SKU, scope trong modal dialog)?

2. Nhóm B - Wait & Ổn Định Đồng Bộ (Smart Waits):
   - Có xuất hiện page.waitForTimeout() hoặc sleep cứng không? (BLOCKER nếu có)
   - Có dùng đúng expect().toBeVisible(), expect().toHaveURL(), hoặc waitForResponse() không?
   - waitForResponse() có được khai báo TRƯỚC thao tác click/submit không, hay có nguy cơ race condition?

3. Nhóm C - TC Mapping & Assertions:
   - Tên test spec có bắt đầu bằng TC ID hợp lệ không? (ví dụ: PARSCA_SCOPE_TC_003)
   - Assertions có đầy đủ, so sánh đúng câu thông báo nguyên văn từ tài liệu BA không?
   - TC gắn tag @CodeHienTai có bị assert sai hành vi mong muốn chỉ để ép test pass không? (BLOCKER nếu ép pass sai)
   - TC gắn tag @GiaLap có kiểm tra việc KHÔNG gọi API cấm và KHÔNG assert "đã lưu vào DB" không?

4. Nhóm D - Test Data & Độc Lập (.agent/rules/test-data.md):
   - Test data có sinh động qua dataFactory.ts (tiền tố AUTO-) và traceable không?
   - Setup có qua API và teardown có tự động dọn dẹp các bản ghi AUTO- không?
   - Các test case có độc lập hoàn toàn, không phụ thuộc vào thứ tự chạy hoặc dữ liệu của nhau không?

5. Nhóm E - Bảo Mật & Clean Code:
   - Có hardcode mật khẩu thật, token, cookie, hoặc in thông tin nhạy cảm ra log/console không? (BLOCKER)
   - Có debug log (console.log), mã bị comment-out, hoặc import thừa không?
   - Quy ước đặt tên file/class/method có chuẩn theo core.md §5.2 không?
