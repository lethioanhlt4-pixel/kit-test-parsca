- Steps:

  2. Nhập Name, SKU (AUTO-PFORM03-{{TS}}), Price 49.99

  6. Bấm "Add Product"

  1. Toast "Saved" hiển thị, chuyển hướng về /vendor/products
  2. Response POST /products trả về status 201, createdBy = chính V1, isNew = true, status = "active"

# CONSTRAINTS
1. Recon DOM trước khi chốt locator: Sử dụng browser headed 1920x1080 (Playwright MCP) theo thứ tự:
   navigate -> resize(1920x1080) -> wait_for(load) -> snapshot -> interact -> screenshot(on_fail).
   TUYỆT ĐỐI không đoán locator từ tài liệu BA.
2. Áp dụng nghiêm ngặt Page Object Model:
   - Locator & UI actions chỉ nằm trong Page Class (kế thừa BasePage).
   - Test spec chỉ chứa các bước Arrange -> Act -> Assert, không viết inline page.locator(...) trong spec.
3. Thứ tự ưu tiên Locator (theo .agent/rules/selectors.md):
   getByRole() > getByLabel() > getByPlaceholder() > getByTestId() > getByText() > id/name > CSS ngữ nghĩa > XPath tương đối.
   Tuyệt đối KHÔNG dùng class hash CSS, utility CSS tailwind ngẫu nhiên hoặc XPath tuyệt đối.
4. Xử lý đồng bộ bằng Smart Waits (Auto-waiting):
   - Dùng: await expect(locator).toBeVisible(), await expect(page).toHaveURL(...)
   - Dùng: const responsePromise = page.waitForResponse(r => r.url().includes('/products') && r.status() === 201) (đăng ký TRƯỚC khi click submit)
   - CẤM: page.waitForTimeout() hoặc sleep cứng.
5. Test Data chuẩn PARSCA (theo .agent/rules/test-data.md):
   - SKU dynamic: AUTO-<MOD>-<Date.now()> (vd: AUTO-PFORM-1729480000)
   - Product Name: Auto <Mod> TC<NNN> <YYYYMMDD>
   - Data setup bằng API (ProductsApi) qua fixture, teardown dọn dẹp bằng DELETE /products/:id (chỉ xoá data có tiền tố AUTO-).
6. Tuân thủ Business Rules cốt lõi:
   - BR-01 & BR-02: Vendor truy cập sản phẩm vendor khác trả về 404 "Product not found" (KHÔNG PHẢI 403).
   - BR-06: SKU & slug duy nhất toàn hệ thống; BE tự chuyển SKU thành chữ IN HOA.
   - Nhãn @CodeHienTai: Nếu test hành vi lệch tài liệu nhưng khớp code hiện tại -> dùng test.fixme() kèm ghi chú Q-Vx, không cố tình assert sai để ép PASS.
   - Màn @GiaLap: Chỉ assert hiển thị, không assert "đã lưu vào database" hoặc ghi bug không gọi API.
7. Title của test spec bắt buộc chứa TC ID và Tag:
   test('PARSCA_PFORM_TC_003 — Tạo sản phẩm tối thiểu thành công @Smoke @CriticalPath', async ({ ... }) => { ... })
8. Test phải chạy độc lập, tự chuẩn bị dữ liệu, chạy thử PASS ổn định 2 lần liên tiếp.
